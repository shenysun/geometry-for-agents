# 阴影走引用，割补走烘焙

阴影面积题要标两图元的重叠部分，割补法要把图形剪成可各自拖走的块。直觉是同一个「多边形布尔」，但曲边交集（两圆的月牙形）没有参数形规范表达（0017），烘焙成 polygon 即折线近似，违背 0006 说明书真源；割补原料全是直边，烘焙无损。两场景对结果的要求也不同：阴影要的是关系与显示，块不需要独立；割补要的恰恰是独立可拖的块。

决定：分家。阴影走引用式——新图元 `overlapFill`（`sources` 两个封闭图元 id + `fill`），不存几何，交集由渲染层离屏合成画出，曲边因此精确；任一源被删则级联删除，源被挪动跟随重绘，创建后被拖到不相交不报错、渲染为空但条目保留（契约只守创建时）；创建是两步拾取工具，非封闭图元、同一图元两次、两源不相交、非 2D 四条契约拒绝；Prompt 投影为一句关系描述，不是坐标。割补走烘焙式——拆分是唯一运算（剪除＝拆分后手删，联合明确不做，块要分开动），被切图元消失，碎片为独立 polygon 继承描边与填充；刀具有两种：闭合直边图元（切完保留）与线段（内部细矩形代切加自动清渣，切完即消失）；曲边图元一律拒绝参与；与被切图元不足两个交点被拒。引擎 Clipper2，同时修正 0009 的二期规划——复杂阴影不再走 Clipper2，它只服务拆分。两个工具都走两步拾取，单选中铁律（同时最多一条）不动；3D 不做。

代价：两种机制并存，词汇必须区分（重叠填充／拆分／刀具）；重叠填充没有几何，不能独立拖动、没有控制点；Clipper2 成为第一个几何外部依赖；线段代切的细矩形厚度要选得够小又不丢交点。

原型验证（`.scratch/prototype/0019-overlap-divide.html`，2026-08）：两步拾取、拖源跟随、不相交渲染为空、级联删除、曲边精确合成、碎片独立拖、画完即回选择全部推过，交互成立。两条实现期教训必须进正式代码：①命中优先级要显式定「面 > 线」——细线（刀具/线段）压在封闭图元上时，点在面内的点击永远归面，demo 里单轮逆序命中让线偷走被切图元的点击，修了两轮；②无填充图元只有细描边，命中需要描边容差（demo 取 10px），否则点在线上偏一点就 miss。demo 的纯模型区（overlapFill 契约拒绝、Sutherland–Hodgman 拆分、级联删除）已按可搬写的形状实现，实现票直接取用。
